MoReV2X command reference
=========================
Everything here runs from the repository root, in a shell that sourced .env.


1. EVERY SESSION
----------------
source .env                     Python 2 for waf, Python 3 and SUMO from .venv, compiler flags.
morev2x_env_off                 Undo it in this shell.

The groupcast simulator is not touched: .env replaces SUMO_HOME in this shell only.


2. FIRST TIME ON A NEW MACHINE
------------------------------
Needs: Xcode command line tools, Python 2.7 (MacPorts python27 here, or set
MOREV2X_PYTHON2=/path/to/python2.7 before sourcing), uv, sqlite3, gsl, libxml2.

tools/bootstrap.sh              Creates .venv, installs SUMO, configures waf, enables the git hooks.
./waf build -j8                 About 10 minutes for a full build, about 900 MB in build/.


3. BUILD
--------
./waf build -j8                 Incremental build.
./waf clean                     Remove objects, keep the configuration.
./waf list                      Programs that can be run.
./waf configure --disable-python --enable-examples --enable-tests --build-profile=optimized --out=build/optimized
                                Needed after adding a module or changing CXXFLAGS in .env.

Debug build, slower, with NS_ASSERT and NS_LOG active, in its own folder:
./waf configure --disable-python --enable-examples --enable-tests --build-profile=debug --out=build/debug
./waf build -j8
Switch back afterwards by repeating the optimized configure line. No rebuild is needed.


4. RUN A SIMULATION
-------------------
Results go to results/<scenario name>/ in the current directory.

Default highway, 100 vehicles, 10 s, SPS:
./waf --run "HIGHWAY --Vehicles=100 --simTime=10 --Periodic --mcs=13"

Faster, without waf checking the build:
build/optimized/scratch/HIGHWAY --Vehicles=100 --simTime=10 --Periodic --mcs=13

Traffic model, pick exactly one:  --Periodic  --Aperiodic  --Mixed --Percentage=50  --ETSI
Scheduler:     --Dynamic  --ReTx  --ReEvaluation  --AllSlots  --UMH  --Adaptive  --AdaptiveRRI
               --RSRP=-128  --PDB=100  --pkeep=0.5  --FreqReuse --ReuseDist=500
PHY:           --mcs=13  --SubChannel=10  --ChannelBW=10  --Numerology=0  --ueTxPower=23
Randomness:    --seed=1  --runNo=1
Extra logs:    --UdpFiles=true  --PosLog=true

Careful:
  --mcs=0 transmits nothing, the MAC treats 0 as "sidelink off".
  --noIBE=false turns IBE off. --noIBE on its own turns it on, the name is inverted.
  --Adaptive and --AdaptiveRRI are different. --Adaptive picks SPS or dynamic by traffic type.
  --AdaptiveRRI changes the RRI and the packet rate from the sensed load.
  All options:  build/optimized/scratch/HIGHWAY --PrintHelp
  Any attribute:  --ns3::NrV2XUeMac::AdaptiveRriMin=50


Parameter sweep, every combination of a YAML file, resumes if interrupted:
tools/run_sweep.py scenarios/sweeps/rsrp_density.yaml --jobs 5
Each key is a HIGHWAY option, and a list is swept. Summary in results/sweeps/<name>/summary.csv.


5. DIFFERENT SCHEDULERS ON DIFFERENT NODES
------------------------------------------
--SchedulerMap="<first>-<last>:<option>+<option>;..."

Options: sps dynamic retx noretx reeval noreeval allslots umh rsrp=<dBm> mcs=<index> pkeep=<p>
         adaptive noadaptive prio=<1..8> preempt prioaware tx=<1..3>
  prio=      SL priority of the node's packets, sent in the SCI. 1 is the highest. Without it: 0, none.
  preempt    pre-emption check at T3 before every announced resource (TS 38.321 5.22.1.1)
  prioaware  RSRP threshold per priority pair and X% per priority (TS 38.214 8.1.4)
  tx=        transmissions per TB of the node's packets: 1 + blind retransmissions, up to 3, all
             within 32 slots. Overrides --ReTx for that node
UE node ids start at 1. Node 0 is the PGW.

./waf --run "HIGHWAY --Vehicles=20 --simTime=10 --Periodic --mcs=13 --SchedulerMap=1-10:sps;11-20:dynamic+retx"

The result of the map is written to results/<scenario>/SchedulerMap.txt.
Columns: node,dynamic,retx,reEvaluation,rsrpThreshold,mcs,pkeep,adaptive,priority,preemption

Priority attributes, for every node at once:
  --ns3::NrV2XUeMac::PriorityAwareSensing=true
  --ns3::NrV2XUeMac::PriorityThresholdStep=3        threshold = RSRP + step*(rxPriority - txPriority)
  --ns3::NrV2XUeMac::ThresRsrpList=<64 values>      sl-ThresRSRP-List, overrides the step
  --ns3::NrV2XUeMac::SizeThresholdList=<8 values>   sl-xPercentage per priority
  --ns3::NrV2XUeMac::Preemption=true
  --ns3::NrV2XUeMac::PreemptionPriority=3           only priorities 1 and 2 pre-empt. 0: any higher one
ReEvaluationsLog.txt has two more columns: kind (0 re-evaluation, 1 pre-emption check) and priority.
SSPSlog.txt has a 24th column, the priority. Trigger 5 is a pre-emption.

Several traffic classes per UE: every multicast group is its own sidelink logical channel and
its own Mode 2 process in the MAC. The flows are served in priority order, a UE sends one PSSCH
per slot (a flow that loses the slot is logged in MacDropLog.txt as intra-ue-conflict), and each
flow leaves out the slots the other flows of the UE reserved. HIGHWAY adds one class to every UE:
--ExtraFlow=<period ms>:<PDB ms>:<payload B>:<priority>:<sps|dynamic>
./waf --run "HIGHWAY --Vehicles=30 --simTime=4 --Periodic --mcs=13 --SchedulerMap=1-30:prio=5 --ExtraFlow=20:20:150:2:sps"


URBAN CHANNEL (TR 37.885 urban grid)
--UrbanChannel=true             UMi street canyon LOS pathloss, LOS or NLOSv by the urban LOS
                                probability, shadowing decorrelated over 10 m
--Buildings=<file.csv>          footprints, one per row: id,x0 y0 x1 y1 ... A link whose straight
                                line crosses one is NLOS: 36.85 + 30 log10(d) + 18.9 log10(fc)
Attributes: ns3::NrV2XPropagationLossModel::Urban, ::BuildingsFile, ::SigmaNLOS (4 dB).
The highway model stays the default and ignores buildings.
./waf --run "HIGHWAY --Vehicles=40 --simTime=3 --Periodic --mcs=13 --UrbanChannel=true --Buildings=buildings.csv"


6. SUMO MOBILITY
----------------
Live coupling over TraCI, ns-3 starts SUMO itself:
./waf --run "HIGHWAY --Vehicles=80 --simTime=10 --Periodic --mcs=13 --sumoCfg=scenarios/sumo/highway_2km/highway.sumocfg --sumoWarmup=90 --PosLog=true"

--Vehicles is the size of the node pool, not the number of cars. If the last line of
the run reports "vehicles without a node" above 0, raise it.
The <end> time in the .sumocfg must exceed --simTime + --sumoWarmup + 1.

Record once, replay without SUMO, gives identical mobility in every run:
sumo -c scenarios/sumo/highway_2km/highway.sumocfg --end 120 --fcd-output results/fcd.xml
tools/fcd2trace.py results/fcd.xml results/trace.csv --begin 90
./waf --run "HIGHWAY --Vehicles=80 --simTime=10 --Periodic --mcs=13 --mobilityTrace=results/trace.csv"

Rebuild the road network after editing the .nod.xml or .edg.xml:
cd scenarios/sumo/highway_2km
netconvert --node-files highway.nod.xml --edge-files highway.edg.xml -o highway.net.xml --no-turnarounds true
cd -


QOS SCENARIOS (multi-class traffic, PQI 21/22/23/89/90/91, numerology 2, 20 MHz, MCS 14)
-------------------------------------------------------------------------------------------
Definitions, configuration and launch: docs/notebooks/10_qos_definitions.ipynb
Results: 11_qos_results.ipynb. Re-evaluation and priorities: 12_reevaluation_priorities.ipynb

Classes:   scenarios/qos/classes.yaml      sizes, rates, PDB, PER, SL priority, SPS or dynamic,
                                            blind retransmissions (1 for PER 1e-4, 2 for 1e-5)
Sweeps:    scenarios/qos/sweep_full.yaml    about 8 h on 30 jobs
           scenarios/qos/sweep_smoke.yaml   every case once, short, about 10 min on 4 jobs

Make a SUMO trace (trace.csv, roles.csv, buildings.csv for urban, meta.json, sumo/):
tools/qos/make_traces.py highway_platoon --density low --seed 1 --out results/qos/traces/hp
tools/qos/make_traces.py urban_intersection --density high --seed 2 --out results/qos/traces/ui
tools/qos/make_traces.py highway_cpm --density 30 --seed 1 --out results/qos/traces/hc
sumo-gui -c results/qos/traces/ui/sumo/scenario.sumocfg       look at it

One run by hand, then its metrics:
tools/qos/sweep.py scenarios/qos/sweep_smoke.yaml --dry-run    the runs and their ids
build/optimized/scratch/QOS --trace=results/qos/traces/hp --flows=<flows.csv> --simTime=10 --ReEvaluation=1 --Preemption=1 --progress=1
tools/qos/metrics.py results/qos/<run>/ results/qos/traces/hp
  QOS options: --Urban=1  --Jammer=x,y,dBm,duty,periodMs,startS,stopS  --BurstLoss=roles|..;goodS;badS
               --PriorityAware=1  --PreemptionPriority=<p>  --Numerology --ChannelBW --SubChannel --mcs
  The flows CSV is what sweep.py writes to results/qos/<sweep>/flows/.

Smoke check before every long sweep, here or on the host:
tools/qos/smoke.sh

Sweeps, here:
tools/qos/sweep.py scenarios/qos/sweep_full.yaml --jobs 8
tools/qos/sweep.py scenarios/qos/sweep_full.yaml --only scenario=highway_cpm --only policy=off|reeval
tools/qos/sweep.py results/qos/qos_full/sweep.yaml --summarise --out results/qos/qos_full
Output: results/qos/<name>/summary/*.csv, per run in runs/<id>/metrics/. Interrupted: run again.

ON THE UBUNTU HOST (32 cores, 128 GB), everything in Docker. Needs git, docker, tmux.
Step by step, with what to check after each step: docs/REMOTE_SWEEP.md
cd ~/Documents && git clone git@github.com:0had0/MoReV2X.git MoReV2X-hadih
cd ~/Documents/MoReV2X-hadih && git checkout feature/qos-evaluation
tools/qos/remote/launch.sh scenarios/qos/sweep_smoke.yaml 8    builds the image, smoke sweep
tools/qos/remote/status.sh qos_smoke                            when it says 0 failed:
tmux kill-session -t qos
tools/qos/remote/launch.sh                                      full sweep, detached tmux session "qos"
tools/qos/remote/monitor.sh                                     tmux session "qos-monitor"
  Ctrl-b d detaches, both keep running after you log out. tmux attach -t qos shows the sweep.
  docker stop morev2x-qos-qos_full stops it, launch.sh again resumes it.
Docker without the scripts:
docker build -t morev2x-qos .
docker run --rm --user $(id -u):$(id -g) -e HOME=/tmp -v "$PWD/results:/opt/morev2x/results" morev2x-qos tools/qos/smoke.sh

Back on this machine:
tools/qos/remote/download.sh user@host qos_full                 summaries and per-run metrics
QOS_SWEEP=qos_full .venv/bin/jupyter lab docs/notebooks/11_qos_results.ipynb


7. TESTS
--------
tools/gate.sh                   Everything: build, ns-3 suites and examples, scenario tests.
tools/gate.sh --quick           Skips the ns-3 suites. Does not unlock a commit.
tools/debug-check.sh            All 29 scheduler, priority, multi-flow and retransmission modes with NS_ASSERT on, about 10 minutes the
                                first time. Run it after changing the MAC: the optimized
                                build ignores assertions, this one found 2 real bugs.
./test.py --nowaf               All ns-3 suites and examples.
./test.py --nowaf -s nr-v2x-mode2       One suite.
./test.py --nowaf -s sumo-mobility
.venv/bin/python -m unittest discover -s tests -v       MoReV2X scenario tests.
.venv/bin/python -m unittest tests.test_integration.SumoMobility -v    One test class.

tools/fingerprint.sh            Hash of the sorted Mode 2 logs of 3 fixed runs. Same output before and
                                after a change proves default behaviour did not move. Valid on
                                one machine and one ns-3 version only.

Logs of the last gate run are in build/gate/.
lte-x2-handover is an accepted failure, listed in tools/known-failures.txt. Anything else
that fails stops the gate. The gate refuses to run on a tree with unstaged changes.


8. GIT
------
The hooks live in tools/hooks and are enabled by tools/bootstrap.sh, or by:
git config core.hooksPath tools/hooks

pre-commit runs tools/gate.sh unless it already passed for exactly the staged content.
Stage everything first: the gate tests the working tree, and any later change re-runs it. commit-msg enforces
Conventional Commits, like "feat(mac): add a per-node RSRP offset".

git checkout -b feature/<short-description>     Never work on main.
git add <files>
tools/gate.sh                                   Runs on the staged tree.
git commit
git push -u origin feature/<short-description>
gh pr create -R 0had0/MoReV2X --base main       Without -R, gh targets the upstream repository.

Remotes: origin is 0had0/MoReV2X. upstream and fork-* are read-only, their push URL is
disabled on purpose.
git fetch upstream                              See what changed upstream.

10. WHEN SOMETHING BREAKS
-------------------------
Thousands of "expected unqualified-id" errors in <version>
    A file called VERSION is back in the root. On a case-insensitive disk it shadows the
    C++ header <version>. This repository uses VERSION.txt.

Simulation crawls, memory grows by GB per minute, SSPSlog stays empty
    The packets carry no V2X tag, so the PDB is garbage. UdpClient::Send and
    PacketSink::HandleRead must stay __attribute__((weak)) in src/applications/model/.
    test_v2x_tag_reaches_the_mac catches this.

"Could not open directory=" in a test
    The test runner finds the source root through VERSION.txt and LICENSE.

"Can not connect to sumo via traci"
    Run the sumo command shown in the message by hand. Usually a wrong path to the
    .sumocfg, or `which sumo` is not the one in .venv because .env was not sourced.

"Sumo was closed unexpectedly"
    SUMO reached the <end> of its .sumocfg before ns-3 finished.

No CBR_OutputFile.txt lines, or a thin ReceivedLog.txt, with custom mobility
    Both logs only cover a window of x coordinates. HIGHWAY widens it in SUMO mode.
    Elsewhere set ns3::NrV2XUePhy::CbrMinX/CbrMaxX and
    ns3::NrV2XSpectrumPhy::MetricsMinX/MetricsMaxX.

Python errors from waf
    `python --version` must print 2.7. Source .env.

A run reports garbage only with --ETSI
    It needs numpy, matplotlib and tqdm in `python3`, which .env maps to .venv.

Disk
    du -sh build results .venv
    results/ folders grow by about 30 MB per 10 s of 80 vehicles.
